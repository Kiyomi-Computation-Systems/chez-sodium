## 1. What M4 delivers

M4 adds no export, and changes none. It writes the pages a reader needs, holds them to the code,
puts them on a site, and makes the first release.

- **Five pages in `docs/`,** each short, ELI5, linked from README.org and the site's nav, in this
  order:
  1. `quickstart.md`, the site's home: what you need, the clone, the library path, a first
     program, which libsodium loaded, running the tests;
  2. `passwords.md`: hash and check, the presets and their cost, custom limits, the login
     pattern, unknown accounts, bounding the password, storing the hash exactly, what `#f`
     means, memory, where hashes live, threads and Ctrl-C, text and normalisation;
  3. `tokens.md`: an API key from `random-bytes`, stored as its `blake2b`, looked up by that hash;
     `constant-time-bytevector=?` for comparing a raw secret; sizes and keys; the entropy abort;
  4. `finding-libsodium.md`: the override, discovery's table, the sonames, the refusals'
     reasons, who needs the override, the load runs once;
  5. `reference.md`: a type glossary, one entry per export (18), the library's load, the
     conditions.
- **`test-reference`,** holding `docs/reference.md`'s signatures to `(chez-sodium)`'s signature
  comments, character for character, as chez-sqlite3's does (§4.2).
- **`test-docs`,** chez-sqlite3's, adapted: every block's kind, every link and anchor, the
  README's twin, the banned words, the export spans, `scheme run` blocks evaluated, whole programs
  run through `gated-command`, the finding page's tables held to discovery's code, and the one H1
  (§4.3).
- **A current README.org,** in the siblings' order, its one Scheme block the twin of a run block.
- **Installing by a clone,** with nothing built: `test-manifest` holds every `git clone` line to
  the manifest's version (§4.4).
- **No page restates a floor:** `check-floors` reads `docs/` (§4.5).
- **The site,** chez-sqlite3's generator copied: chez-cmark-gfm a second `depends/dev`;
  cmark-gfm, `tar` and `xz` in the container; a sixth CI job, `site`; a second workflow,
  `pages.yml`, deploying on a `v*` tag; both held by `check-ci` (§4.6, §4.7).
- **The comment pass:** about 26 lines in 15 files that carry decision numbers, "amended" or the
  brief's sections, and five comments that say what the code does not (§4.8).
- **0.1.0:** CHANGELOG.md's entry, `Akku.manifest` at 0.1.0, the clone lines at `v0.1.0`, the tag
  signed by the owner, a GitHub Release, the site deployed by the tag (§4.9, §4.10).

**Not in M4:** a new export, or a change to one; tightening `password-needs-rehash?` (§2.1, Q1);
an Akku publish (brief §11.8); an arm64 job; an `examples/` directory; Tier 2, which is M5.

### 2.2 The finding behind Q1, as the caller reran it

Set B found that `password-needs-rehash?` answers `#f` for hashes `password-hash` never makes
([research/m4-plan/b/](research/m4-plan/b/README.md) §6, D2 and D3). Before the question went to
the owner, the caller reran it at both releases, with set B's `probes/other-tag.sps` and its own
`probes/truncated-tag.sps`, each through `both.sh`:

| Hash, at `(make-password-limits 1 8)` | verify | needs-rehash, at its limits |
|---|---|---|
| exact, 93 characters | `#t` | `#f` |
| argon2id with a 16-byte tag, 72 characters, built with `crypto_pwhash` | `#t` | `#f` |
| a 64-byte tag, 136 characters | `#t` | `#t`: 128 characters or more, libsodium answers -1 |
| `x` appended | `#f` | `#f` |
| the last character dropped | `#f` | `#f` in 22 to 26 of 400 random hashes, over two runs at each release (`out/truncated-tag.out` keeps one); otherwise `#t` |

**Set B's "differs by release" was randomness.** A tag of 42 base64 characters decodes only when
its last character's spare bits are zero, about 1 time in 16, at either release. The caller
corrected the record.

The trade-offs put to the owner:

- **No string check can find a damaged hash.** One tag character changed keeps the shape and the
  length exactly. Only `password-verify`, with the password, can.
- **Tightening would cost a written constant.** libsodium has no function for the tag's size,
  `STR_HASHBYTES` 32 in `pwhash_argon2id.c`. A release that changed it would make every new hash
  read as stale, so every login would rehash.
- **Tightening would gain only one thing:** an imported hash in another shape moves to
  libsodium's at its next login. Techo makes every hash it stores with `password-hash`.

## 3. The documents' facts

Every note "Owed to M4" was checked against the code and the real library by set B, at both
releases ([research/m4-plan/b/](research/m4-plan/b/README.md) §2). The pages state them as below.
"Confirmed" means set B measured the note as written.

**From M1:**

- **The first reference under an engine,** and **on two threads at once:** confirmed, quoted from
  ADR-0007, amended. Reference the library once, on one thread, before engines or threads reach
  it.
- **`sodium_init`'s 1** (an earlier init, by the program or another library): confirmed. The load
  accepts it.
- **What wiping cannot reach:** confirmed. The caller's own string or bytevector, the
  bytevectors a verb returns, and copies the collector leaves behind.

**From M2:**

- **The cap:** confirmed. Every input, and `random-bytes`' output, is at most 64 KiB. A hash string
  counts characters, a password its UTF-8 bytes. Any password of at most 16384 characters always
  fits: UTF-8 takes at most 4 bytes a character (inferred from UTF-8; not probed).
- **The compare leaks only the lengths:** confirmed.
- **The entropy abort, corrected.** With no entropy source at all, the process aborts when the
  library loads, because `sodium_init` stirs the generator (`core.c:40`, then
  `randombytes_sysrandom.c:281`). `random-bytes` aborts only if the source fails later.
- **`blake2b` can raise `&sodium-failed`:** confirmed, by its contract. No release reaches it.

**From M3:**

- **What `#f` means, corrected.** It means a wrong password, a hash libsodium cannot read, or
  memory libsodium could not get, and nothing tells them apart. To guess at memory, hash a
  throwaway string at the caller's current limits after a `#f`: a `&sodium-failed` there means
  memory is short.
  - Under short memory a wrong password also reads as short memory.
  - It sees only a failure libsodium is told of, as under `ulimit -v`. "Or with no overcommit" is
    measured nowhere, and the pages leave it out.
  - It fits only hashes made at the caller's current limits.
- **A container's memory limit kills the process:** measured now. Under a 512 MiB cgroup with no
  swap, a `'sensitive` hash and verify were killed, exit 137, at both releases, and nothing was
  raised. The pages say to size a container for each hash that can run at once: 64 MiB at
  `'interactive`, more at the higher presets.
- **A hash's own limits set what verifying it costs:** confirmed. An `'interactive` hash edited to
  `m=1048576,t=4` took 1.8 s to answer `#f`. Hashes come from storage only you can write.
- **The login pattern:** confirmed. `password-needs-rehash?` only after `password-verify` answers
  `#t`, since it answers `#t` for `"garbage"` and `""`.
- **A password changed by another thread during the call is refused:** confirmed, as
  `changed-during-call`.
- **A password over the cap is refused by `password-verify`, widened.** It raises, as
  `over-the-cap`, even against an unknown account's dummy check; a password that is no string,
  such as `#f` from a missing form field, raises `not-a-string`. A login form checks for a string
  of at most 16384 characters first, or catches `assertion-violation?`.
- **The hash string is stored exactly, widened.** Any change, not only a space or a newline, makes
  it verify `#f` for ever. `password-needs-rehash?` may still answer `#f` for it (§2.2).
- **The calling thread's interrupts wait while a hash runs, corrected.** Ctrl-C, timers and engine
  expiries on the hashing thread wait about 50 ms at `'interactive`, and about 2 s at
  `'sensitive`, measured on the development workstation. Other threads run on, so hash on a worker
  thread.
- **An unknown account, corrected.** Verify the password against one real hash made at the
  current limits, and refuse whatever it answers. Any string that is not a real hash answers in
  microseconds, against about 50 ms, which tells the two apart: a string the pre-check passes,
  such as `"*"`, as much as one it refuses.
- **Custom limits go to both `password-hash` and `password-needs-rehash?`:** confirmed.
- **No normalisation:** confirmed. `"café"` in NFC and in NFD each verifies only against its own
  hash.
- **The rehash can raise `&sodium-failed` after a `#t` verify:** confirmed. Wrap it; if it fails,
  keep the old hash and log the user in.

**Each time is the development workstation's.** The pages say "about 50 ms here", never a
promise. The records' "about 55 ms" was M3's measurement on the same machine; set B's medians are
49.0 to 50.5 ms.

**What a page may not say:**
- either floor's version text, so no page quotes the version the floor's library prints, nor the
  unthreaded-Chez refusal, which holds the Chez floor (§4.5);
- a finding id, an ADR, a date, "yet", "unreleased" or "slice" (§4.3).

### 4.3 `test-docs` (ADR-0013, decision 4)

chez-sqlite3's rules, adapted ([research/m4-plan/a/](research/m4-plan/a/README.md) §4):

- **Kept as they are:**
  - every block names `scheme`, `sh` or `text`;
  - every Scheme block is a fragment Chez's `read` reads, or runnable;
  - relative links and anchors resolve, by GitHub's rule, and none points into `.plans/`;
  - README.org links every page, and its Scheme block is the twin of a `scheme run` block;
  - no page says `ADR-`, `TODO`, any "yet", "unreleased", "slice", a `.plans` path or a
    `YYYY-MM-DD` date;
  - every page has one H1, its first line.
- **The export spans:** a code span of one name beginning `sodium-`, `chez-sodium-`, `password-`
  or `make-password-`, or exactly `random-bytes`, `blake2b` or `constant-time-bytevector=?`, is an
  export of `(chez-sodium)`.
- **`scheme run`:**
  - the body of `(let () …)` in an environment of `(rnrs)` and `(chez-sodium)`;
  - its `;; => DATUM`;
  - the block count zero after.

  `(rnrs)` has no `bytevector` and no `import`: a block uses `u8-list->bytevector`.
- **A whole program,** a block whose first datum is `(import …)`:
  - it runs in a fresh Chez from a fresh directory, `src` alone on its path, through
    `gated-command`;
  - it exits 0, with nothing on stderr, and prints the text block that follows it;
  - a password program prints a verify's `#t`, never a hash.
- **A guarded program,** one holding a clause `(sodium-library-unavailable? V)`:
  - it prints `(sodium-version)`, as the suite reads it;
  - it runs again with `CHEZ_SODIUM_LIBRARY` naming a file that is not there, and prints one
    datum whose first element is `refused`.
- **No whole program names a `(chez-sodium private …)` library.**
- **`finding-libsodium.md`'s tables are the code's:**
  - the reasons table's first column is `sodium-library-unavailable-reasons`, in its order;
  - the discovery table's rows are discovery's two worlds, Guix and other Linux. Each names
    `libsodium-candidates`' paths on x86_64 and arm64, and `libsodium-sources`' sources, in order.
- **Every word holding `CHEZ_` is `CHEZ_SODIUM_LIBRARY`,** and each value a line sets is absolute.
- **Left out:** the examples twin rule, and the "leaves a file" clause.
- **The limits.** A password block may hash at the default, the exception Q3 chose (ADR-0011,
  amended). Its cost under the gate was measured by set A: about 0.7 s a hash or a verify, 4.9 s
  for each whole program, about 60 s for the suite in the container, against the 450 s line.
- **Every rule is held on the suite's own texts before it reads a page,** and each is watched
  failing by a planted fault, as chez-sqlite3's was.

## 5. The slices

review on Opus, and its fixes. Each keeps a mutation log, `.plans/m4-slice-N-mutation-log.md`.
Builders write no commit; the caller commits, pushes and opens each PR.

**Every brief restates these:**
- the comment rule;
- the suite rules that bind what it builds: the exit form, a guard around anything that can raise
  with a sentinel of its own, no `#f` expected from something that can raise, whole outputs;
