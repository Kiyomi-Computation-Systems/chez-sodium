## 1. What M1 delivers

From brief §9, and the pieces M0's plan §3 left to M1:

- **Conditions:** ADR-0006's tree, the raise helpers, `shown-value`, and the refusal of a
  secret by its kind (§4.1, items 2 and 3).
- **The load:** discovery, the one load, the floor read from `sodium_version_string`, and
  `sodium_init`, in ADR-0002's order (`discovery`, `load-state`, `verify`, `native`).
- **`sodium-version`,** exported by `(chez-sodium)`.
- **The block helper:** counted blocks (`memory`) and `call-with-block`, wiped by one
  `sodium_memzero` just before the free; and one section per verb, `call-in-section` (§4.2,
  item 5).
- **The checks of the FFI:** the decoy, the C oracle `libsodium-oracle`, `test-constants`'
  prototype check against `sodium.h`, the convention table and `check-seam`.
- **CI's `floor` and `current` jobs;** `main` runs `make build` by discovery, asserts that it
  loaded the floor, and runs `check-dev`.
- **`make build`, `make dev` and `check-dev`.**

**`(chez-sodium)` arrives in M1.** A verb is a name `(chez-sodium)` exports (global constraints,
"What is bound"; brief §4), and M1 delivers `sodium-version`. It also exports the predicate and
accessors of `&sodium-library-unavailable`, so that a program can catch a refused load by type.
`docs/reference.md` and `test-reference` wait for M4 (brief §9). The signature comments are
written now.

## 4. Decisions

Each gives a recommendation, its evidence, and whose it is.

### 4.1 Owed to M1 (`progress.md`)

1. **The reason for a version string that is not three naturals.**
   - **Recommendation: `below-floor`,** its detail the string, or `#f` for NULL. The floor check
     accepts only a version it can show is at the floor, and refuses everything else.
   - Evidence: libsodium answers `"1.0.18"` and `"1.0.22"`, from a static string (§5.1). A seventh
     reason would edit brief §5, ADR-0002 decision 6, ADR-0006 decision 2 and the constraints, for
     a string no release answers. One rule, "accepted only when read as three naturals at or above
     the floor", covers NULL, a malformed string and a lower one alike, in the one place the
     string is read.
   - Alternatives: a seventh reason, `unreadable-version`; or `load-failed` for NULL, naming the
     entry point, as chez-sqlite3 refuses a NULL `sqlite3_libversion`.
   - **The owner's.** It amends ADR-0003, decision 2.
2. **`&sodium-failed`'s fields.**
   - **Recommendation: `function`,** the C function's name as a string, `"crypto_pwhash_str"`,
     **and `code`,** the integer it answered. The verb is the condition's `&who`.
   - Evidence: ADR-0006 says "the verb, and what libsodium answered". chez-sqlite3 names the verb
     by `&who` alone (its ADR-0013, decision 2), and `&sqlite-closed` carries nothing else.
     Neither field is a secret.
   - **The owner's.** It amends ADR-0006, decision 3. The type is built in M1, raised in M3.
3. **Whether conditions carry `&who`.**
   - **Recommendation: yes, every raise.** The load's refusals name `chez-sodium`: no one
     procedure raises them. Every other raise names the public verb, and carries a `&message`.
     A refusal of a caller's mistake leads its irritants with a symbol naming the rule.
   - **A secret's refusal** is `(refuse-secret WHO RULE PARAMETER VALUE)`: an assertion
     violation from WHO, irritants `(RULE PARAMETER (kind K))`, K being `(kind-of VALUE)` whatever
     VALUE is, and never its length.
   - Evidence: chez-sqlite3 ADR-0013, decision 2 and its slice-4 amendment, so rows assert who and
     irritants and never a message. ADR-0006, decision 6.
   - **The owner's,** with item 2. That a secret is named by its kind alone is settled by
     ADR-0006, decision 6; the irritants' layout is this plan's.
4. **Whether the load registers an exit check.**
   - **Recommendation: no, and M1 removes them:** `register-exit-check!` and `exit-checks` from
     `counters`, `run-exit-checks` from the testing library, and their rows in `test-counters`
     and `test-chez-sodium-testing`.
   - Evidence: chez-sqlite3 registered `sqlite3_memory_used`. libsodium keeps no count of its
     own, and the block count is already `suite-exit-status`' own check. M2 and M3 add none.
   - **Settled** by the M0 plan, §2: "If none does, M1 removes them". ADR-0011 is amended to
     record the difference from chez-sqlite3 ADR-0005 at v0.1.1.
5. **The C oracle's name: `libsodium-oracle`.** `tests/libsodium-oracle.c`, compiled at test time
   under that name, driven by `tests/libsodium-oracle.sls`, run through `gated-command`. M0's gate
   already holds the name (`check-memory-gate` case q). **Settled** by ADR-0011.
6. **The decoy logs each pointer through a `volatile uintptr_t`.**
   - Restated for slice 3's brief, and for every later milestone's decoy entries: a pointer is
     read as `volatile uintptr_t p = (uintptr_t) ptr;`, and only `p` is tested.
   - Evidence (§5.1): `p ? … : …` on `randombytes_buf`, which `sodium.h` marks `nonnull`, fails
     `-Werror=nonnull-compare` on GCC 16.2 against 1.0.22; through the volatile it compiles.
   - **`sodium_memzero` has no `nonnull` attribute at 1.0.22,** so the ternary compiles there.
     None of M1's five can show the trap: the rule must be applied, not discovered.
   - **Settled** by brief §7.2 and AGENTS.md. ADR-0011 gains it, so a record carries it.

### 4.2 New questions

1. **`(chez-sodium)`'s exports in M1.**
   - **Recommendation:** `sodium-version`, `chez-sodium-error?`, `sodium-library-unavailable?`,
     and `sodium-library-unavailable-reason`, `-path`, `-source`, `-detail` and `-candidates`.
     Predicates and accessors only, never a `&` name or a constructor (chez-sqlite3 ADR-0013,
     amended). `sodium-failed?`, `sodium-failed-function` and `sodium-failed-code` join in M3,
     with the first raise.
   - That the public library arrives is **settled** (§1). **The names are the owner's,** as
     chez-sqlite3's maintainer approved its list.
   - **A new record, ADR-0012,** holds the public library and the seam (§4.3). No record does
     today: ADR-0001, decision 9, holds the two FFI names alone.
2. **Which entry points M1 binds: five.** `sodium_version_string`,
   `sodium_library_version_major` and `_minor`, `sodium_init`, and `sodium_memzero`, which the
   block helper needs. Each later milestone binds its own verbs' entry points, appended to the
   load's last step, each with its row in the convention table, the decoy, the missing-api rows
   and row 22. The forms, each plain, each the whole second argument of `bind-required`, with
   the prototype its convention row writes in 1.0.22's `sodium.h` spelling:

   ```scheme
   (foreign-procedure "sodium_version_string" () uptr)            ; const char * (void)
   (foreign-procedure "sodium_library_version_major" () int)      ; int (void)
   (foreign-procedure "sodium_library_version_minor" () int)      ; int (void)
   (foreign-procedure "sodium_init" () int)                       ; int (void)
   (foreign-procedure "sodium_memzero" (uptr size_t) void)        ; void (void *const, const size_t)
   ```

   - Evidence: chez-sqlite3's M1 bound its load's 15 and its M2 added 21. ADR-0005: a function
     is bound for a named use, and "a test on every supported libsodium" comes with it.
   - **This plan's,** within ADR-0002 and ADR-0005.
3. **The load's steps,** as native's ordered definitions (ADR-0002, decision 4; X-m4):
   - 0, once: a recorded failure is raised again;
   - 1, choose; 2, load: a raise is `load-failed`, its detail the loader's message;
   - 3, the version entries: bind all three, call each once. A NULL string is `#f`;
   - 4, the floor: `check-version`. Major and minor are recorded, never compared;
   - 5, `sodium_init`: bind, call once, record the answer. 0 and 1 load (item 12 below);
   - 6, the rest: `sodium_memzero` in M1.

   **This plan's,** by ADR-0002.
4. **Where major and minor are reported.** In native's private `loaded-libsodium`, a fresh list
   each call: `((path . P) (source . S) (version . V) (major . N) (minor . N) (init . A))`.
   `make build` prints them as `version: 1.0.18 (library 10.3)`, and the refusal probe prints the
   list. `sodium-version` answers the string alone (brief §4), and no condition carries them:
   ADR-0006 gives five fields. `init` is `sodium_init`'s answer: rows 21 and 22 read it.
   **Settled** by ADR-0003, decision 3; where is this plan's.
5. **`call-in-section` and the load under an engine.**
   - **`call-in-section : (-> A) -> A`:** THUNK's answer, run in one `critical-section`. A raise
     inside is caught there, by a guard that takes every object, and raised again, the same
     object, once the section has ended. THUNK answers data, and a verb raises what that data
     says after the call. That is ADR-0007, decisions 2 to 4, as one procedure.
   - **`sodium-version` holds no section.** It makes no block and calls no C: it copies a
     string native read at the load. Row 18 still runs it under an engine. ADR-0007's amendment
     says so. **The owner's** to accept, with the amendment.
   - **The load under an engine (measured, §5.1).** A library body first reached inside an engine,
     the engine abandoned after the body has started, wedges the library: every later reference
     raises "cyclic dependency involving invocation of library". Resumed, it completes. A program
     that references any of the library's bindings, anywhere in its text, runs its body before its
     first line, outside any engine (measured; importing alone does not). A reference reached
     through `eval` runs it at that reference, which can be inside an engine (measured); so,
     unmeasured here, can a script's or the REPL's top level.
   - **A section narrows it, and nothing closes it.** An engine spends no ticks inside a section,
     so with the body's work in one, only an abandon in the prologue before the section wedges
     (slice 0's review; reproduced, `engine-section.sps`). The first draft said a section defers
     the expiry to its end: false.
   - **Decision (the owner, after slice 0's review):** native's load runs in one section. Its
     steps' refusals, raised by our own pure code, are taken by `call-in-section`'s guard inside
     the section, as data, and raised again after it through `load-step`. No caller's handler
     runs inside. A trap in `traps.md`; the documents say it, in M4; and every engine row
     references native once before its first engine (ADR-0007, amended).
6. **Which helpers M1 builds.**
   - **Recommendation:** `call-with-block`, `call-in-section`, `call-with-bytes`, `foreign-bytes`,
     `c-string->bytevector` and `c-string->string`. M2 needs these and nothing else.
   - **`call-with-c-string` and the password's UTF-8 writer wait for M3,** their one user.
     v0.1.1's `call-with-c-string` makes two Scheme copies of its string, `string-copy` and
     `string->utf8`, which ADR-0008 forbids for a secret. Without the copy, another thread can
     change a character between the count and the write, and a different UTF-8 length would
     overrun the block. So M3's writers bound every write by the block's size, and answer a
     changed string as data. Owed to M3.
   - **This plan's.** Brief §7.2 keeps `call-with-c-string` in native; it arrives in M3.
7. **`check-seam`'s rules.**
   - **Rule (l) is dropped.** It made `(chez-sqlite3 private utf8)`'s strict decoder the only one,
     because Chez's `utf8->string` drops a leading U+FEFF. Every string libsodium hands back here
     is ASCII: the version, the prefix, a hash string. So no text needs it.
   - **A new rule (m): only `native` imports `(chez-sodium private memory)`, and no library

   - **This plan's;** ADR-0012 records both. Rule (m) has no source, so its rows are written and
     watched to fail like any new check.
8. **Row 24's helper half.**

     `watch_set(ptr, n)` names a block; `watch_verdict()` answers 0 for not freed, 1 for freed all
     zero, 2 for freed holding a non-zero byte.

   - **This plan's,** by ADR-0008 and ADR-0011.
9. **`test-constants` keeps its name,** though M1 holds only prototypes. ADR-0001, decision 10,

10. **How `main` asserts that it loaded the floor.**

## 6. The slices

One PR each, in order. Each ends with a read-only adversarial review on Opus, and its fixes. Each
keeps a mutation log, `.plans/m1-slice-N-mutation-log.md`, in the newer form: Guards, Mutation,
Result, Clean rerun.

**Every brief restates these,** since a rule fixed in one slice came back in the next
(chez-sqlite3's slice 2):

- tests assert a reason symbol, who and irritants, and whole outputs: never a message;
- nothing raises inside a critical section or a critical `dynamic-wind` thunk;
- anything that can raise is computed under a guard, with a sentinel of its own;
- no expected value is `#f` from something that can raise;
- `let*` where one init must follow another; `for-each` for effects;
- every engine row references the library once before its first engine (§4.2, item 5);
- each suite ends with `(exit (suite-exit-status runner))`;
- a child that reaches native code starts through `gated-command`, and asserts `(valgrind . yes)`
  exactly when the gate asked; the wipe child alone runs outside;
- every new check is watched to fail before it counts;
- briefs name sources, not counts: "every rule v0.1.1 holds for these jobs", never "11 rules";
- an engine spends no ticks inside a section: assert the outcome at every fuel, never an expiry;
- a red run against a check that refuses the whole input proves no row: turn each rule off
  instead;
- a scanner of forms reads elements, never tails;
- GNU `env` reads `-u` only before its first assignment;
- anchor a row on a line's content, never an occurrence count;
- a program naming an unbound identifier dies before its first line: watch new-export rows fail
  against stubs that are present and wrong;
- Valgrind logs carry the checkout's path: scrub them before committing;
- a witness has a standing positive control: row 24's child also frees a block unwiped, verdict
  2, and leaves one unfreed, verdict 0.
